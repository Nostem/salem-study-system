### Migration notes for the owner

- `20260610_auth_rate_limit_and_consistency.sql` creates the `auth_rate_limit`
  table, repoints the `system_reviews` FK to `profiles`, and adds the
  `question_attempts (quiz_session_id, question_id)` unique index. The unique
  index is `WHERE quiz_session_id IS NOT NULL` so historical session-less
  attempts (none exist today) are unaffected.
- Existing learners who claimed quiz "mastered" state at 2/2/0 will keep their
  current `mastery_state` value until they next submit a quiz; the new
  3-attempt FSRS threshold only applies on the next write. No backfill is
  needed.
- Any invite issued before 20260429 that still has only `code` (no
  `code_hash`) must be re-issued via `generate_invites.py` because the
  signup function no longer accepts plaintext codes.
- A new `ALLOWED_ORIGINS` env var can override the default allowlist if you
  ever deploy to a non-`nostem.github.io` origin. Format: comma-separated
  origins, e.g. `https://nostem.github.io,https://preview.salem.example`.

## Recommendations — needs a product/owner decision

1. **Mastery thresholds disagree between the two write paths.**
   `submit-quiz-results/index.ts:67` marks a question `mastered` at 2 attempts / 2 correct / 0 incorrect;
   `_shared/fsrs-whole-question.ts:65` requires 3/3/0 and also demotes to `shaky` on any lapse.
   A question can be "mastered" by a quiz and then demoted by the next review. Pick one
   canonical rule (the FSRS one is newer and stricter) and use it in both paths. Not changed
   here because it alters user-visible mastery state.
2. **Quiz re-submission double-counts.** `submit-quiz-results` deletes/re-inserts the session
   snapshot, but `question_attempts` inserts append and `user_question_state` increments from
   the current DB value — a client retry after a network timeout inflates attempt counters.
   Fix by making the submission idempotent (unique constraint per session+question, or
   delete prior attempts for the session before insert).
3. **Invite signup**: (a) lookup still accepts legacy plaintext codes via
   `.or(code_hash.eq…,code.eq…)` — migrate remaining plaintext invites to hash-only and drop
   the `code` path; (b) the check-then-update flow is a TOCTOU race under concurrent claims of
   the same invite (loser gets a misleading 409 after its auth user is cleaned up).
4. **CORS is `*` on all edge functions** (`_shared/http.ts`). Authenticated endpoints should
   reflect a small origin allowlist (`nostem.github.io`, localhost) instead.
5. **Rate limiting** exists only on `contact-feedback`. `username-login` and `invite-signup`
   are brute-forceable; extract the rate-limit pattern into `_shared/` and apply it there first.
6. **Accessibility tests don't run in CI.** `@axe-core/playwright` is installed and
   `tests/ui-test.ts` exists, but it's not in the smoke list. Add it once current violations
   (if any) are triaged, or run `test:ui:full` as a nightly job.
7. **No lint/format tooling** (no ESLint/Prettier for the site, no ruff for Python).
   Worth adding once, cheap to keep.
8. **Focus management in quiz-v2 play/review**: prev/next navigation leaves focus on the
   button; move focus to the new question heading for screen-reader users (WCAG 2.4.3).
9. **`system_reviews.user_id` references `auth.users` directly** while every other table
   references `profiles`. Re-point the FK for consistent cascade behavior.
10. **Slug-alias duplication** between `build_static_quiz_bank._slug_aliases()` and
    `exam_question_import.slug_variants()` — intentionally *not* consolidated here because
    generated data files are diff-checked in CI and slug behavior differences would change
    output. If consolidating, regenerate all bundles in the same commit.
11. **Theme colors are hard-coded hex values** sprinkled across pages; moving them to CSS
    variables would make theme changes one-file edits.
12. **CI duplicates work** (smoke and build jobs both `npm ci` + Astro build). Sharing the
    build artifact between jobs would save ~1 min/run.

## Audit findings rejected as false positives

- "Shell injection in `scripts/dl`" — all variables are correctly quoted; no issue.
- "`actions/checkout@v5` is outdated, downgrade to v4" — v5 is the current major; no change.
- "history.astro swallows errors silently" — the catch deliberately falls back to the
  login panel, which is the correct behavior for an auth-gated page.
- "`?count=999999` is a DoS vector" — `count` only slices the already-filtered question
  array (~500 items max); oversized values just return the whole pool.
